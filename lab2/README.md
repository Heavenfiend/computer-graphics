# Лабораторная №2. Камера и освещение

Вариант существующей первой работы: правильный додекаэдр (вариант 10).
Реализация на C++20, Vulkan, GLFW и ImGui. Основа скопирована из текущей `lab1`;
сама первая работа и её незакоммиченные правки не изменялись.

В PDF `Lab #2 Camera and Lighting` на странице 2 прямо указано: на оценку 5
нужно выполнить базовое задание и все дополнительные задания. Здесь реализованы
базовое задание и дополнительные пункты 1–4. Окончательную оценку ставит преподаватель.

## Сборка и запуск

На этом компьютере достаточно открыть `BUILD.cmd`, дождаться завершения,
затем открыть `RUN.cmd`. Запускать нужно именно из папки `lab2`, поскольку
пути к скомпилированным шейдерам относительные.

Из PowerShell:

```powershell
cd C:\KG\lab2
.\tools.ps1 -Action Build
.\RUN.cmd
```

`tools.ps1` находит существующий SDK в `../VulkanSDK/1.4.321.1` или через
`VULKAN_SDK`, затем вызывает CMake. Используются исходные версии зависимостей:
GLFW 3.5.1, vk-bootstrap v1.4.321, VMA v3.4.0, ImGui v1.92.9.
Если уже есть исходники библиотек в `lab1/build-debug/_deps`, CMake использует
их повторно; на другом компьютере загружает закреплённые версии через FetchContent.
Новые библиотеки не добавлялись.

Для самостоятельной настройки из окружения с CMake и SDK:

```powershell
cmake --preset msvc-debug -A x64
cmake --build build-debug --config Debug --parallel 4
ctest --test-dir build-debug -C Debug --output-on-failure
```

В CLion открыть `lab2`, выбрать MSVC, цель `vulkan-starter-app`, рабочую папку `lab2`.

## Управление

- `Camera`: позиция, pitch/yaw/roll, FOV, проекция, near/far, размер ортографической области.
- Вне полей интерфейса `WASD` перемещают камеру вперёд/назад/вбок, `Q/E` — вниз/вверх относительно камеры.
- Перетаскивание правой кнопкой мыши вне окна ImGui поворачивает камеру.
- `Objects and materials`: выбор одной из двух фигур, трансформации, альбедо,
  цвет блика, shininess, цвета вершин и анимация с паузой/сбросом.
- `Ambient and directional`: цвет/сила ambient, направление лучей, цвет/сила направленного света.
- `Point lights` / `Spot lights`: кнопка добавления, раскрываемые настройки каждого
  источника и кнопка удаления. Число источников внизу показывает актуальные размеры массивов.
- `Show light markers and cones`: цветные кубы источников и белые каркасы прожекторов.
  `Cone display length` меняет только длину изображения конуса, не закон затухания.
- Длинное окно ImGui прокручивается; его размер ограничивается текущим окном приложения.
- Все параметры сцены хранятся в памяти; новый запуск возвращает начальную сцену.

В шейдерах нет фиксированного максимума числа источников: используются runtime arrays.
CPU-буферы растут по мере необходимости. Единственное ограничение количества —
реальный `maxStorageBufferRange` устройства, который проверяется перед добавлением/выделением.
Пустым массивам соответствует валидный минимальный буфер и count=0.

## Что понимать для защиты

1. Матрицы хранятся по столбцам, вершина вычисляется как `P * V * M * p`.
   `M = T * Rz * Ry * Rx * S`. Матрица вида — обратное преобразование камеры.
   Ось Y мира направлена вверх; исходный взгляд камеры направлен вдоль `-Z`.
   Проекция учитывает реальный aspect framebuffer, глубину Vulkan `[0;1]` и смену знака Y.
2. Нормаль нельзя умножать на обычную матрицу модели при неравномерном масштабе.
   Нужна обратная транспонированная линейная часть. Для `M=T*R*S` это `R*S^-1`.
   В std140 три столбца normal mat3 занимают 48 байт. Нулевой масштаб запрещён в UI.
3. Освещение считается в мировом пространстве. `N` — нормаль, `L` — направление
   от фрагмента к источнику, `V` — к наблюдателю, `H=normalize(L+V)`.
   Для перспективы `V=normalize(cameraPosition-worldPosition)`, для ортографии
   `V=-camera.forward`, поскольку лучи параллельны.
4. Используется стандартный Blinn–Phong:
   `ambient*albedo + sum((albedo*max(N·L,0) + specularColor*max(N·H,0)^shininess)*radiance)`.
   Блик отбрасывается при `N·L<=0`. У point/spot `radiance=color*intensity/r²`.
   Именованный epsilon защищает только сингулярность `r=0`; искусственных
   линейных/постоянных слагаемых затухания нет.
5. Направление directional/spot задаёт направление распространения лучей.
   Поэтому для directional `L=-direction`, а у spot угол сравнивается с `-L`.
   Углы в UI — **полууглы**: полный раствор конуса равен удвоенному внешнему углу.
   Между `cos(outer)` и `cos(inner)` свет плавно возрастает от 0 до 1.
   При равных углах получается жёсткая граница; нулевое направление заменяется `-Z`.
6. Set 0 общий для сцены, set 1 свой для каждой модели. Размеры и padding
   структур CPU совпадают с GLSL. Storage buffer — массив данных внутри одного
   дескриптора, а не массив дескрипторов.
7. Здесь один кадр в полёте. `prepare` ждёт fence до обновления mapped-памяти
   и смены SSBO. После CPU-записи VMA выполняет flush. При resize framebuffers
   уничтожаются до image views, пересоздаются зависимые ресурсы и семафоры.
   Явные render-pass dependencies связывают acquire, сцену и ImGui.

PDF не закрепляет конкретный порядок Euler-поворотов, управление клавишами или
начальные параметры. Они выбраны как обычные настройки реализации.
Лекция 4 непосредственно использована для камеры, освещения, двух sets и SSBO;
лекция 3 — для атрибутов/буферов/дескрипторов. Лекция 5 просмотрена и не добавляет
требований к этой работе. Текстуры, area lights и тени не требуются и не добавлялись.
Для формул используются согласованное `P*V*M` и стандартная модель Blinn–Phong:
отдельные подписи порядка преобразований и запись diffuse на слайдах 3–4/18
лекции 4 неоднозначны, а PDF требует именно камеру и Blinn–Phong.

## Демонстрация преподавателю

1. Запустить новую сцену, показать две фигуры, Camera position/yaw/FOV и обе проекции.
2. У выбранной фигуры отключить Vertex colors, менять Albedo, Specular color,
   Shininess и Scale по одной оси. Показать анимацию, паузу и сброс.
3. Временно убрать point/spot, показать один directional, изменить его направление
   и интенсивность, затем ambient. При всех интенсивностях 0 фигуры чёрные.
4. Добавить несколько point, изменить Position/Color/Intensity, отдалить источник.
   Удвоение расстояния от источника до **одной и той же точки поверхности**
   уменьшает его вклад в четыре раза при неизменных углах и других параметрах.
5. Добавить spot, направить на фигуру, менять Inner/Outer half angle.
   Для наглядности уменьшить остальные источники и ambient. Сравнить мягкий
   край при outer>inner и жёсткий при outer=inner.
6. Показать/скрыть цветные кубы и конусы, изменить направление/угол прожектора.
   Развернуть/восстановить окно, показать обновление проекции без искажения пропорций.
7. Показать shader с `pointLights[]`/`spotLights[]` и два descriptor set в `createDescriptors`.

## Проверки и их пределы

Проверки проведены 19.10.2026 на Windows, MSVC 19.44, SDK 1.4.321.1,
AMD Radeon(TM) Graphics. После исправления найденных ошибок выполнены:

- Debug и Release сборки.
- CTest с проверками камер/проекций, преобразований нормалей, всей сетки и конуса.
- Дополнительно `lab2-input`: настоящий обработчик камеры проверен для WASD/QE,
  нормализации диагональной скорости, перемещения при повёрнутой камере,
  поворота ПКМ, ограничения pitch и захвата клавиатуры/мыши ImGui.
  Оба теста проходят в Debug и Release.
- Компиляция всех четырёх shaders и `spirv-val --target-env vulkan1.0`.
- Скрытые runtime-прогоны в нескольких размерах окна с включённым
  VK_LAYER_KHRONOS_validation и synchronization validation.
- Визуальная проверка функций, перечисленных в таблице, включая живой resize.
  В итоговом интерактивном прогоне диагностических ошибок/предупреждений не было.
- В окончательной сборке визуально проверены все шесть клавиш WASD/QE,
  конечная сцена и сворачивание/восстановление окна. Логи Vulkan чистые.
  Проверка ПКМ выполнена подачей заданного состояния ImGui в настоящий обработчик;
  инструмент управления Windows не поддерживает физическое перетаскивание ПКМ.
- Неверные CLI-параметры (`--frames 0`, `--hidden` без лимита кадров,
  нулевой размер окна) корректно отклоняются с кодом ошибки.

Повторить автоматические проверки уже собранного Debug:

```powershell
.\tests\verify.ps1
```

Проверить Release в той же multi-config папке:

```powershell
cmake --build build-debug --config Release --parallel 4
.\tests\verify.ps1 -Configuration Release
```

Скрипт проверяет CTest, наличие включённого слоя, завершение 120 кадров при
1280×720, 960×540 и 900×900 и отсутствие validation warnings/errors в обоих логах.
Логи сохраняются в `build-debug/validation-*.log` (игнорируются Git).
Обычный RUN сохраняет `runtime-output.log` и `runtime-errors.log`; сообщения
стандартного Vulkan debug callback могут попадать в stdout, поэтому смотреть надо оба.

Автотесты не заменяют визуальную проверку. Не выполнены сравнение GPU-пикселей
с эталонным решением, количественное измерение фотометрии, длительный stress-test
на предельном числе источников и проверки других GPU/ОС. Сочетания всех возможных
значений UI не перебирались. Эти ограничения не являются обещанием абсолютного
отсутствия ошибок или гарантией оценки.
